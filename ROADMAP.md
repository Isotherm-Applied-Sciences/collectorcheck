# CollectorCheck Roadmap

This roadmap outlines the planned development milestones for CollectorCheck, the open‑source receipt verification gateway maintained by Isotherm Applied Sciences Inc. The roadmap is iterative and may evolve as the project grows.

---

## Vision

CollectorCheck aims to become the standard open‑source gateway for validating receipts, provenance records, and purchase documentation. The long‑term goal is to provide a transparent, reliable, and extensible verification pipeline that can be used by collectors, archivists, institutions, and developers.

---

## Guiding Principles

- Minimal, deterministic architecture
- Transparent verification logic
- Local-first processing
- Modular components
- Easy for contributors to extend
- Easy for institutions to audit

---

## Current Version: v1.0.0

The initial release includes:
- Receipt upload and verification
- Basic metadata extraction
- Tamper-check heuristics
- Simple frontend viewer
- Flask backend API
- Local SQLite storage
- MIT license

---

## v1.1 — Verification Enhancements

Planned improvements:
- More robust metadata extraction
- Additional tamper-detection heuristics
- Improved checksum validation
- Better error reporting
- Frontend UI polish
- More detailed verification output

Goals:
- Increase accuracy of verification
- Improve clarity for end users
- Strengthen the reliability of the pipeline

---

## v1.2 — Developer Experience Upgrade

Planned improvements:
- Expanded API documentation
- More example payloads
- CLI helper tool
- Better logging and diagnostics
- Optional verbose mode for debugging

Goals:
- Make CollectorCheck easier to integrate
- Improve developer onboarding
- Reduce friction for contributors

---

## v2.0 — Advanced Verification

Major features:
- Multi-receipt batch verification
- Provenance scoring system
- Receipt similarity detection
- Optional cloud sync module
- Configurable verification profiles

Goals:
- Support institutional workflows
- Provide deeper provenance insights
- Enable large-scale verification tasks

---

## v2.1 — Extensibility Framework

Planned improvements:
- Plugin architecture for custom validators
- Third-party module support
- Configurable metadata extraction rules
- Custom tamper-check pipelines

Goals:
- Allow organizations to extend CollectorCheck
- Support specialized verification needs
- Encourage community-driven modules

---

## v3.0 — Enterprise & Archival Features

Major features:
- Long-term archival mode
- Immutable verification logs
- Exportable verification certificates
- Multi-user roles and permissions
- Organization-level dashboards

Goals:
- Support museums, archives, and institutions
- Provide durable verification records
- Enable multi-user workflows

---

## Future Exploration

Potential long-term ideas:
- Machine learning-assisted tamper detection
- OCR-based receipt reconstruction
- Integration with Dadtabus identity substrate
- Integration with HydroPass and Gradient Engine
- Cross-receipt provenance linking

These items are exploratory and may evolve.
